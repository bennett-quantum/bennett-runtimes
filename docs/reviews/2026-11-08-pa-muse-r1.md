## Blocking findings

**P1-1 — oracle — brt-zni — `scripts/native-check.cpp:98-116,177-187`.**
`stackArgBytes` counts named stack operands, but `va_start`'s overflow pointer
already skips them. With seven named `int`s and one variadic `int`, it publishes
16 bytes at the start of the sole 8-byte variadic slot. A callee doing two
successive volatile `va_arg(ap,int)` reads exits 0 with empty stderr, accepting
the out-of-bounds second read. It must fault 7. A register-only negative control
does fault 7. Ran `python3 -B "$R/abi-probes.py"`; `named-stack-overread` returns
0 on LLVM18/23. Ran `python3 -B "$R/runtime-controls.py"`; checked IR confirms
`va_push(i64 16)`. Receipts: `abi-probes.txt`, `runtime-controls.txt`; sources and
checked IR retained in `tmp/abi-probes/`. This weakens the native comparison oracle.

**P1-2 — gate / no narrowing — brt-1gt — `scripts/native-check.cpp:95`.**
The new classifier aborts on a valid 32-byte-aligned byval argument to a
variadic callee, even when the callee never calls `va_start`. Minimal source:
`typedef float V __attribute__((vector_size(32)));`
`__attribute__((noinline)) static int ignore(int n,...) { return n; }`
`int main(void) { return ignore(0,(V){1,2,3,4,5,6,7,8}); }`.
Clang O0 passes this as `ptr byval(<8 x float>) align 32`. The same input links
and exits 0 against pre-fix `d6a4f80`; HEAD fails checked linking with
`LLVM ERROR: unmaterialised over-aligned variadic stack argument` on both majors.
Ran `python3 -B "$R/wide-vector.py"`; receipt `wide-vector.txt`, source
`tmp/wide-vector/input.c`. This is a new rejection of a previously working
general variadic call, not a pre-existing unsupported case.

**P1-3 — gate (rung-3 binding) — bennett-driver-6bs — driver `gate.toml:43`.**
The new runtimes pin breaks the existing default binding test and consequently
the mandatory `cargo test` check at `gate.toml:10-12`. Ran driver
`cargo test --offline -j3 --test native_scalar -- --nocapture --test-threads=4`:
printf passes, but binding fails (exit 101), expecting `BD-E-NATIVE-STARTUP` and
receiving `BD-E-NATIVE-ADAPTER` / `BD-E-NATIVE-INPUT` at the transport-clock alias.
Ran driver `python3 -B "$R/pin-attribution.py"`: the unchanged fixture and
driver executable pass on LLVM18/23 with original runtime pin `248e468`, and
fail identically with `d6a4f80`. Thus **the upstream incompatibility predates the
varargs fix, but this branch newly adopts it into the driver gate**. Existing
`bennett-driver-vzv` documents that upstream cause; it does not establish a
pre-existing failure at the driver's actual base pin. Receipts:
`driver-focused.txt`, `pin-attribution.txt`, `binding-{old-driver-pin,runtime-base}.txt`.
