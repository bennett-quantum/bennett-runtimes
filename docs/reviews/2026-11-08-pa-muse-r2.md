## Additional register-save precision check

**P2, brt-7id; no rule-7 oracle P1 demonstrated.** At
`scripts/native-check.cpp:41,192–194`, the adapter registers 176 bytes of
backend save storage. Ran `python3 -B .tmp/rev-pa-muse-r2/register-slots.py`
through the wrapper: one GP int passed/two volatile int reads and one FP double
passed/two volatile double reads both exit 0 with empty stdout/stderr on 18/23.
Zero arguments of either class/one read also exits 0; valid controls exit 0.
Receipt `register-slots.txt`, sources, checked IR and assembly are retained in
`tmp/register-slots/` beneath the review directory.

The whole area is **not guaranteed initialized argument storage**. System V
ABI §3.5.7 permits omitted saves and uses `%al` to avoid unnecessary XMM saves;
the zero-double probe's assembly reserves its frame but skips every XMM save.
See the primary [ABI source, Register Save Area and va_start](https://gitlab.com/x86-psABIs/x86-64-ABI/-/raw/master/x86-64-ABI/low-level-sys-info.tex).

Caller-argument-count precision is nevertheless not required by this checker's
published allocation/lifetime contract. Pinned dialect 0.2.13,
`1c29c8d731228b67902c3fa72e410e1bb71d16b4`, §§17.5/17.7 requires detecting
out-of-live-allocation accesses on the **same materialised module** and reporting
source-definedness coverage separately. These raw reads remain within the
callee's live backend save frame; a missing C argument is source UB
([N1570 §7.16.1.1p2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)).
Dialect §14.3 N23 instead materialises an exact caller va block and forces the
memory path. Its bounds remain required; comparing that transformed program
with this raw diagnostic would not establish same-module oracle disagreement.
Thus the whole live save object may be registered for allocation checking;
it must not be advertised as complete missing-argument or initialization
detection. `brt-7id` records the coverage limit and overly broad test wording.
